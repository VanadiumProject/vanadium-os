## What 1.0 Means
Two things the MVP does not require, and 1.0 cannot ship without:
1. It runs on the **real JH7110**, not only in the emulator.
2. It is a **whole console**, not the minimum that counts as one -- sound, a way in for a
   game that is not baked into the image, and failures a person can read.

- For the boot chain this lands on, [see also](../04_OS_VanadiumOS/Boot.md).
- For the hardware it targets, [see also](../03_Hardware/SoC_Choice.md).

## From MVP To 1.0
### The Console Gets A Voice
Audio. The MVP is deliberately mute; a shipped console is not. No driver and no design yet,
so this begins as a document, not a commit.

### Failures Become Legible
The [Safety Modes](../04_OS_VanadiumOS/Safety_Modes.md) mechanism, wired past the CPU module.
The MVP has the fatal-trap consumer; 1.0 has real codes for memory, storage and input as those
subsystems come online. A shipped console that fails silently is the one thing the design
opened by refusing.

### The Machine Stops Wasting Itself
Harts 1-3 stop being parked. The core-allocation decision from
[Execution Model](../02_Architecture/Execution_Model.md) gets made and implemented, and the
timer interrupt turns a single running program into something that can be scheduled. The MVP
does not need preemption; a console that will outlive one game does.

### A Game Arrives On A Cartridge
The MVP loads from whatever the emulator hands it. 1.0 loads a real game from real storage,
with an identity, [see also](../06_Game_layout/Cartridge.md) and
[see also](../06_Game_layout/Game_ID.md). This is where the SDK's output stops being a test
binary and becomes a thing a player owns.

## Bring-Up On Real Hardware
The emulator has been generous, and generosity hides walls. Each of these is invisible until
the first real boot:
- **DRAM base.** The linker carries the emulator's `0x80200000`; the JH7110 is likely
  `0x40000000`. [See also](../02_Architecture/Memory_Map.md).
- **UART access width.** The offsets are already JH7110-shaped, but `REG8` may need to be
  `REG32` if the part is `reg-io-width = 4`.
- **The boot image.** U-Boot will not take a bare ELF; it needs a real image at an address
  that matches the linker.
- **The counter's rate.** `timebase-frequency` from the device tree, so timestamps are true
  on the board and not just in QEMU.

>"None of these are hard. All of them are the kind of wrong that says nothing until the moment
> it says everything. The plan is to meet them on purpose, one at a time, with the emulator
> still available as the thing that worked yesterday."

## What 1.0 Still Does Not Owe Anyone
1.0 is a finished console, not an open platform. Held back to [after launch](Post_Launch.md)
on purpose:
- Memory protection between the OS and a game.
- More than one game resident, menus, a shell.
- The expansion connector and its accessories.
- A boot chain that is entirely ours.

### Conclusion
>"1.0 is not the biggest version we can imagine. It is the smallest version we would be proud
> to hand someone and say: this is finished, now go understand it."
